# 局限与未解问题

> English: [05-limitations.md](05-limitations.md)

## 覆盖率是内容形状的

剩下 58% 的记录管线主要是采集时从未走到的内容。它们首次用到时仍会编译（观察到 100–600 ms 的帧，
偶尔到秒级）。循环收敛的速度只跟你玩新内容的速度一样快，而全新设备上的全新安装，起点就是构建随包
的那份语料。

## 设备相关的档案

Metal 4 管线档案由设备驱动为那个 GPU 和 OS 版本生成。它们在这里把预热从 31.2 s 砍到 7.0 s，但不可
再分发，必须按设备家族分别采集。

## 语料本身不可分发

`corpus.zip` 和 `pipelines.tsv` 派生自游戏的着色器与管线状态。因此本仓库不含它们，也不含任何采集
产物；公开的只有钩子和合并工具。

## 启动成本是搬家，不是消失

预热是每份新内容的一次性成本：这个构建首帧 7.5 s，设备档案齐了之后约 0.2 s。它有界、可见，但仍然
是启动时间；在低内存设备上，语料 + 档案还会和游戏抢内存。

## 单设备、单游戏版本

这里所有数字都来自一台 iOS 26、Metal 4 的 iPhone 和一个游戏构建。编译时间、档案兼容性和线程饱和点
在其它 GPU 上都会不同，而语料 key 绑死在确切的游戏/更新版本上。

## 未解问题

- 能不能从管线状态（colour mask、targets）预测缺失的着色器对，而不是每个新变体都要玩一遍？
- 在加载画面里编译（而不是首帧）能不能把 7.5 s 完全藏掉？
- 剩下的 58% 里，有多少是正常游玩到不了的，有多少只是还没去到？
